## 1. 收集目标与范围

建立能直接支撑城市比较、不可补偿底线、稳健偏好分析和后续改进的数据包。数据包同时保存研究所用数值、分子分母、误差、地域对应、来源说明和获取条件。最终核心指标约 14—20 项；为计算和检验这些指标，需要保存更多底层字段。

采用三层范围：

| 层次 | 本次收集内容 | 用途与边界 |
| --- | --- | --- |
| A 核心 | 25 城的七领域候选数据，人口和学生分母，地理标识，误差和覆盖资料 | 支撑当前模型；先保留同类候选测量，再按口径与覆盖选用 |
| B 扩展 | 同一来源近年可比序列，学校/社区分布，低收入等分组，现成可达性统计，独立验证数据 | 检验年份稳定性、不平等、代理偏差及后续模型修订；可得且相关的现成文件本次收齐 |
| C 条件储备 | 原始事故记录、必要的历史 GTFS、招生边界、活动时间/费用、公开研究微观数据 | 对应明确模型用途。免费、可访问、规模合理的相关数据本次归档；全国巨量原始包及逐机构手工调查，先做需求和入口清单，证明有必要后实施 |

“未来可能需要”落实为已提出的改进方向，不无限扩展到所有城市资料。某项只存入口时，明确标为“储备入口”，不得记为已经收集数据。

数据取得次序：**官方现成统计表/批量数据集 → 官方研究或论文公开数据 → 可靠机构数据 → 按统一定义处理原始记录 → 有限人工核查。** 不先从地图逐个数设施，也不先自己重建全国公交网络。论文用于寻找成熟测量、开放数据与阈值证据，不把论文中的一个城市样本外推成全国统计。

## 2. 城市、年龄、年份与地理规则

### 城市与年龄

- 用 Census **Vintage 2025** 同一版人口排序表 `SUB-IP-EST2025-ANNRNK` 的前 25 个城市条目冻结候选池，保存官方名称和代码；DC、合并市县及 balance 条目依该表的具体口径记录，不凭名称自行替换边界。
- 面向 14—18 岁、公立高中、不能日常依赖汽车接送的学生。来源采用 12—18、16—19、9—12 年级等不同分组时分别记录，不能默认为精确覆盖目标年龄。
- ACS 常用公开年龄分组不能直接拼成精确的 14—18 岁人口。能取得精确分母则使用；否则明确采用相近年龄/在校人数代理及其误差，不能悄悄按年龄均匀拆分。
- 三城试采按冻结人口排名第 1、13、25 名选取，检查规模跨度；全 25 城另外做文件覆盖检查，三城成功不等于全部成功。
- 全部 25 城保留在总表。至少十城完整比较是题面下限，不以方便下载为由先删掉难采城市。

### 年份

- 本轮资料可得性核查截止 2026-11-11。实际下载还要保存下载时间；如出现新发布文件，登记更新，不自动覆盖已经冻结的版本。
- **主分析先评估 2024 年附近的共同数据窗口**；依据 25 城覆盖表选择每个指标的同版数据。另保留最新可用快照，做年份敏感性分析。不存在所有来源同为“2026 年观测”的假设。
- ACS 城市比较可用已发布的 2025 一年估计，2024 一年估计用于共同年份比较；城内分布使用已发布的 2020—2024 五年估计。五年估计是整个期间的估计，不能标作单年观测。
- 已核实的其他版本包括 EPA 2025 年年度数据、IMLS FY2024、FTA 报告年 2025、TPL 2026 版、HRC 2025、CRDC 2021—22。版本新旧分别记录；首次下载需再次核对文件内年份及修订状态。
- 对犯罪、交通死亡、污染等年度指标收集 2021—2025 中已发布且可比的年份，用于波动诊断；缺年和系统变更单列。年度重叠的 ACS 五年估计不能当独立年度样本。
- 保存 `observation_period`、`release_date`、`revision/vintage`、`retrieved_at` 四类时间。FY2027 HUD 租金标准是财政年度标准，不能冒充 2027 年实际租金调查。

### 地理匹配

以 Census place 标识候选城市，保存 county、CBSA、tract/block group、NCES 学校/LEA、FBI ORI、公交机构、图书馆系统/网点 ID 的对应关系。不同来源按其空间作用记录：

- 城市居民的犯罪风险与警察辖区覆盖匹配，不能仅凭警局名字匹配。
- 学校位置、学区边界、学生居民所在地及实际招生资格分开。先产出可取得的学校供给代理；缺乏招生资料时不能称其为每名居民的可入读机会。
- 都会区价格或空气数据可以作为区域背景，不能改标签成城市精确值；同一都市区的多个城市会共享部分测量。
- 图书馆系统活动量、公交机构运量不能全部归给总部所在地。没有服务区分摊依据时保留系统层级。
- 社区跨市边界时优先使用更细人口或官方对应表；按面积分摊只作注明的近似，并检验边界影响。

## 5. 获取失败如何判定

用户提出的三类原因均保留，另设“证据不足、待核实”，避免把未知原因强行归类。数据是否公开与某个下载通道是否可用分开记录。

| 结论 | 所需证据 | 后续动作 |
| --- | --- | --- |
| 云端通道受限，其他环境可访问 | 同一官方文件在云端失败、在另一个实际测试环境成功；若宣称“用户实体电脑可访问”，必须有该电脑的测试结果 | 保存两端时间、URL、响应与有效文件证据；再提供具体人工下载清单 |
| 需要注册/密钥/付费/申请/许可 | 官方条件、登录提示或合同条款；把收费、免费注册、邮件申请、再分发限制分别注明 | 优先免费文件或开放替代；确需用户操作时一次汇总要求和成本，不擅自购买或代发申请 |
| 指定数据在要求范围内无法取得 | 官方未发布/停发/不覆盖、统计抑制、数据已撤下等明确证据，且查过合理替代 | 指明究竟缺哪一年、哪城、哪年龄和哪字段；选择合法代理、缩小结论或保留缺口 |
| 原因待核实 | 403、超时、JS 页面、搜索不到链接、工具不支持文件格式，尚不能区分原因 | 尝试官方下载、普通浏览器、官方镜像/档案及论文数据入口；记录最后状态 |

HTTP 200 也可能返回“Missing Key”网页；须核对内容类型和文件内容。工具说“不支持 CSV/XLSX/ZIP”不等于来源拒绝下载。官方页面公开可查也不等于数据文件已经取得。云端浏览器依然是云端环境，不能替代用户实体电脑的访问测试。

每个失败项记录：来源/目标字段、精确 URL、实际测试日期与环境、请求方法、HTTP 状态或工具错误、内容类型/页面说明、已尝试的替代路线、证据支持的结论、下一步。没有实际记录的状态码不得补写。

只在完成来源目录、官方发布说明、可比替代和公开研究数据检查后，才报告“在指定口径下无法获取”。未查完的项目继续标待核；最终报告必须单列，不能用“全部完成”掩盖。

## 6. 数据整理与验证

保留来源文件原貌，另生成标准化长表和城市宽表。数值之外至少包含：城市及源地域 ID、指标与字段名、值与单位、分子分母、年龄/年级、观测期间、版本、MOE/区间及置信水平、缺失/抑制原因、来源定位、空间转换、代理类型、文件和脚本版本。

主要检查：

1. 文件能解析且内容与预期数据一致，记录行数、字段、年份和覆盖；API 错误网页不计入成功。
2. 城市代码和边界正确；学校、机构、监测站存在重复或跨区服务时处理清楚。
3. 来源缺失码、抑制区间、零、未报告和不适用分开；底线资料缺失不得标为已通过。
4. 比例分母相符、汇总数可对照官方现成结果；抽查典型城市和异常值，所有影响资格的异常单独核验。
5. 核对年份和年龄是否混用；原始值保留，极端风险不能缩尾后进入安全底线。
6. ACS MOE 依对应文档转换；推导比例/汇总误差遵循官方方法，不能把相关分项当作独立样本随意相加。
7. 最终输出 25 城 × 候选指标覆盖矩阵、适用模型表、取舍理由与未解决缺口。统计质量不能由“下载成功”替代。

## 7. 推送与长线交接

所有可合法再分发的已收集数据推送至 `moiddales/qwerty` 的 `claude/affectionate-mayer-ihqczh`。源文件、提取数据与标准化数据分别保存，处理脚本和代码本同行；每个完整批次推送，不把同步拖到最后。

建议项目内文件布局：

| 路径 | 内容 |
| --- | --- |
| `data/raw/<source>/<version>/` | 取得并允许归档的原始文件及必要说明 |
| `data/extracted/` | 可追溯的城市/学校/社区提取结果 |
| `data/processed/` | 模型用长表、宽表、误差和资格输入 |
| `data/metadata/` | 来源与字段字典、地域映射、文件清单、许可、访问记录和覆盖表 |
| `analysis/` | 提取、校核和模型脚本，各步骤参数 |
| `DATA_COLLECTION_STATUS.md` | 确认后创建：各来源进度、实际已推送内容、阻塞与接手动作 |

下载清单记录每份源文件的原始 URL、版本、字节数与校验值，供重现及大文件归档；来源文件不因清洗而覆盖。API 密钥和登录凭据不入仓库。

GitHub 普通 Git 限制单文件不超过 100 MiB。小型 CSV/JSON 和文档直接提交；必要大文件选择同仓库 Release 归档或核实可用的 LFS，项目清单给出定位和校验值。先优先取得相关城市/州数据或现成汇总，避免无必要地下载全国 1 GB 原始包。仓库读取已验证，数据上传方式按文件大小实际验证；不能把未上传文件写成“已推送”。

已发现 ParkServe 和商业评分有明确使用/再分发条件。受限原始文件不擅自转存；登记条款、取得步骤与开放替代，采用可合法发布的数据完成主数据包。私有仓库也不能默认获得第三方转授权。若某受限来源不可替代，将其作为具体待决项报告。

每次重大更新继续保存用户要求原文、日期、改动、验证、已推送提交和下一步。必要的独立来源核查可使用最多三个 GPT6-Astra 子代理，主代理负责版本、字段和地理整合；不会让多个代理重复下载同一公共底表。

## 8. 执行顺序与验收

| 阶段 | 动作 | 完成标准 |
| --- | --- | --- |
| 0 本轮 | 核查入口，提交本方案及访问证据，等待用户确认 | 有具体清单和已知限制；没有把来源发现写成数据采集完成 |
| 1 确认后试采 | 下载城市排序、人口/地域底表；三城试采；检查全 25 城源文件覆盖 | 冻结城市名单、字段字典和版本选择；列出会改变核心测量的缺口 |
| 2 A 层全量 | 批量取得核心现成数据，统一标识，按七领域补齐 | 每个候选字段都有数值与口径，或具体缺口和替代决定 |
| 3 B 层与适用 C 层 | 收齐相关多年/分组/空间分布和独立验证数据；检查需要的细粒度储备 | 每份储备写明将支持哪项研究；入口与已取得文件清楚区分 |
| 4 缺口解决与核对 | 逐项尝试有效替代，必要时汇总用户端下载/账户事项；复核原始与清洗结果 | 失败分类有证据，关键统计定义统一，完成覆盖与质量报告 |
| 5 最终归档 | 推送可再分发文件、脚本、说明和状态，核实远端提交 | GitHub 上可找到实际数据，已取得/未取得/受限/待核逐项列明 |

确认一次后在授权范围内持续实施；普通格式、清洗和来源替代不反复请求确认。收费、必须用户登录或会改变研究范围的缺口才汇总提出具体决定，同时继续其他来源。

完成数据阶段意味着范围内的项目都有可核验结局，并且可用数据与代码已归档；不等于把所有空格填成数字。若尚有原因不明的关键缺口，报告“主体数据已完成、该项待核”，不宣称完整数据收集已结束。

## 9. 确认记录
