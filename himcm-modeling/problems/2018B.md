# 2018B: Cozy Smart House

## The task in brief
The system must learn irregular departure/arrival and sleep/wake events, save energy while preserving comfort, use outside conditions and humidity/allergen information, compare existing systems and extend to multiple zones.

## What makes this problem hard
The team builds a hierarchy of event matching, a thermal ramp-time estimate and comfort/standby/off modes. A humidity and heat-index layer adjusts the set point, and the multi-person extension prepares for the earliest predicted return across zones.

## Common ground

- The system is decomposed into event prediction, thermal response and a control policy.
- Irregular schedules are handled by broadening the historical matching set when exact examples are sparse.
- Comfort and energy are treated as a trade-off, with humidity or heat-index information included.
- The news release and competitor discussion connect the model to a homeowner decision.

## Different routes that all worked

The event hierarchy is the clearest reusable component; thermal regression and comfort modes can be swapped for richer building physics later. The multi-zone extension should retain the same prediction-to-control interface.

## Ideas worth borrowing for similar problems

- Event histories are matched first by same day type and then by broader evidence. Recent HVAC response pairs estimate time to comfort. Modes switch based on predicted absence and ramp time; humidity thresholds and heat index modify comfort.
- Heat-gain plots support proportional ramp time; a sample irregular week exercises the event logic; competitor and strength/weakness sections test scope (pp. 9–21).
- The event hierarchy is a practical way to handle irregular schedules without assuming a 5+2 week. The mode design makes the comfort/energy trade-off visible and leaves a clear path to multiple zones.

Keep prediction, thermal response and policy mode separate so each can be calibrated. Report event-prediction error, sensor missingness and occupant-conflict cases. Humidity and allergen constraints should be tied to cited thresholds, and competitor comparisons should use the same criteria.

## Comparative synthesis

The sole carded paper, Team 9247, gives the problem a complete event-to-control pipeline. Its return-time algorithm first looks for comparable events on the same day of the week, then same day type, and finally all recorded events when the history is sparse (9247, pp. 5–8). A separate sleep/wake routine distinguishes events likely to have an alarm from those predicted by average sleep duration (9247, pp. 7–9). Recent pairs of HVAC times and temperature changes estimate how long the home needs to reach comfort; heat-gain plots support the approximately proportional response assumption (9247, pp. 9–11). Comfort, standby and off modes then trade energy against readiness, while humidity and heat index alter the effective set point (9247, pp. 12–16). For multiple occupants and zones, the system prepares for the earliest predicted return and compares its design with Ecobee4 and other systems (9247, pp. 16–21).

The main lesson is modularity. Event prediction can be evaluated with held-out departures, returns, sleep and wake times; thermal response can be calibrated separately; and the control policy can expose a readiness margin. A new model should report errors for irregular schedules, missing sensors and conflicting occupants, and compare energy with a stated baseline such as a conventional weekly schedule. Humidity, allergens and air quality need sensor and threshold definitions. The paper’s news release is useful because it turns these modules into homeowner benefits without requiring the reader to understand the equations.


## Detailed comparison

The paper’s main contribution is the separation of prediction from control. The return routine is a hierarchical data-matching rule; the sleep/wake routine handles alarm-like regularity differently from irregular sleep; and the thermal model estimates how early the system must begin heating or cooling. Comfort, standby and off modes then implement a policy rather than hiding it inside the predictor. This modularity makes it possible to replace the empirical ramp-time equation with a richer building model later while preserving the event interface.

A complete extension should define a validation split: hold out known leave/return and sleep/wake events, report absolute timing error and false early/late preparations, then test a week with irregular errands. It should also report energy against a named baseline and show how humidity changes the effective comfort temperature. For multiple occupants, earliest predicted return is conservative but may waste energy when one resident’s schedule is uncertain; the model should state how conflicting preferences are aggregated and when zones can be independently controlled. Competitor comparison should use the same criteria for Enthalpy, Ecobee4 and any other systems: manual correction burden, irregular-schedule behavior, humidity/air-quality handling, zones, transparency and failure recovery. The news release should retain the practical benefits while the technical sections expose data requirements and error cases (9247, pp. 5–21).

Because only one carded paper is available, the problem card should make its evaluation plan explicit. The next useful evidence would be held-out event histories and measured HVAC response under different outdoor temperatures; both would test the assumptions that currently carry the most weight.

A useful first field test would compare predicted and observed return preparation times for a week, then measure energy and comfort complaints against a conventional schedule. Those results would calibrate the next version.

The technical card should also state what happens when no comparable event exists. A conservative default temperature schedule or a manual override is part of the system design, even if the paper’s primary goal is to remove manual corrections.

This also makes the comparison honest: the model’s benefit is reduced manual scheduling, while its risk is prediction error when the household changes behavior.

The result is a testable household-control proposal rather than a claim that one schedule fits every resident or climate.

It also leaves a clear measurement plan for the next iteration.

Those measurements support an evidence-based update.
