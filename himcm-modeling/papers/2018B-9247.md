# 2018B-9247: Enthalpy Smart Home Climate Control

## At a glance
The team proposes Enthalpy, a thermostat that learns departure, return, sleep and wake events without a fixed weekly schedule. It retrieves comparable past events, predicts return/wake times, estimates HVAC ramp time from recent temperature changes, and chooses comfort, standby or off modes. Humidity and heat index modify the set point; multiple occupants and zones are handled by earliest predicted return and zone-specific schedules. (pp. 1–3).

## How they read the problem
They translate every requirement into an observable event or control mode. Leave and sleep events are classified by day type and history; irregular events fall back to broader matching. The model uses simple empirical responses instead of an unverifiable full building simulation. They keep the official deliverable in view and use stated assumptions to make the decision variables finite (pp. 3–6).

## Models and methods
Hierarchical nearest-event averaging predicts return and wake times (pp. 5–8). Linear regression of recent heating/cooling pairs estimates time-to-comfort (pp. 9–11). Comfort, standby and off modes trade energy and readiness; humidity thresholds and heat index adjust comfort (pp. 12–16).

## Data
The paper uses synthetic event histories, HVAC response experiments and humidity/comfort references. The paper uses event histories, temperature/humidity sensors and recent HVAC response pairs, with published comfort, humidity and smart-thermostat references. The worked week and heat-gain plots are illustrative tests. It distinguishes prompt values, cited constants and generated scenarios so that a reader can see which inputs would need recalibration for a new setting (pp. 4–8).

## Assumptions
This team assumes access to temperature, humidity, event and smart-home sensor histories, and that recent HVAC response predicts future ramp time. Event matching falls back from same-day evidence to broader history when data are sparse. User preferences and humidity constraints are modeled as inputs; the multi-zone rule prioritizes the earliest predicted return (pp. 3–11). Its central choice is event-time prediction, supported by sleep/wake classifier; those choices determine which behavior is visible in the reported results (pp. 4–8).
## Validation, sensitivity and robustness
Experimental heat-gain plots support the proportional ramp-time assumption (p. 11). A sample week tests irregular schedules, and strength/weakness and competitor sections compare Ecobee4 and other systems (pp. 16–21).

## What makes it stand out
The event hierarchy is a practical answer to irregular schedules and cold-start data. Modes expose the comfort/energy trade-off, while humidity and multi-person extensions remain tied to the same prediction pipeline.

## Writing and presentation worth learning
A news release opens the paper; algorithm diagrams, heat-gain plots, a sample schedule, comparison table and multi-zone discussion make the system approachable (pp. 1–3, 5–21).

## Notes for reuse
- Predictions rely on enough prior events and assume recent thermal response transfers forward. An imitator should quantify prediction error, handle missing sensor data and test conflicting occupant preferences explicitly.
